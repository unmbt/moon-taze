## 1. 固定测试数据与隔离

所有常规测试使用临时项目、独立缓存、FakeRegistry/FakeClock/FakeFileSystem；不得请求真实 Mooncakes 或写入仓库根清单。API 契约、版本比较、过滤和补丁结果优先使用明确断言；文本布局、诊断结构可使用审查过的快照。

### F-01：版本梯

依赖名 `demo/lib`，当前声明 `1.2.0`，`latest_version = 2.0.0`。默认关闭成熟期。所有时间均为下表日期的 `00:00:00Z`，固定 now 为 `2026-01-15T00:00:00Z`。

| 版本 | 发布时间 | 撤回 |
| --- | --- | --- |
| 1.1.9 | 2026-01-02 | false |
| 1.2.0 | 2026-01-03 | false |
| 1.2.4 | 2026-01-04 | false |
| 1.3.0 | 2026-01-07 | false |
| 1.9.0 | 2026-01-08 | false |
| 2.0.0 | 2026-01-09 | false |
| 2.1.0-beta.1 | 2026-01-11 | false |
| 1.8.5 | 2026-01-12 | false |
| 3.0.0 | 2026-01-13 | true |

该梯度故意让发布顺序与 SemVer 顺序不同。测试以原序、逆序和固定洗牌顺序分别提供，结果必须相同。

### F-02：兼容边界

分别使用以下独立版本集；latest 取每组最大的稳定版本。

- 当前 `0.2.3`；候选 `0.2.4, 0.2.9, 0.3.0, 1.0.0`。
- 当前 `0.0.3`；候选 `0.0.4, 0.0.9, 0.1.0`。
- 当前 `1.2.3-beta.2`；候选 `1.2.3-beta.10, 1.2.3, 1.3.0-rc.1, 1.3.0`。

### F-03：清单和工作区

清单基础文本如下；格式测试另加 BOM、CRLF、中文、emoji、tab、尾注释及无末尾换行变体。

```text
name = "demo/app"
version = "0.1.0"
// 示例版本不应被修改：demo/lib@1.2.0
import {
  "demo/lib@1.2.0", // 保留这条注释
}
description = "import { \"fake/module@9.9.9\" }"
```

工作区含 `apps/a`、`libs/b` 两个成员；a 依赖 b 及外部 `demo/lib`。另设不属于该工作区、却与 b 同名的外部目录，以及 `_build`、`.mooncakes`、嵌套 `.git`、嵌套 `moon.work`、目录链接和用户忽略目录。

### F-04：可控服务和故障注入

HTTP 替身可按请求 key 返回合法 JSON、404、429+Retry-After、5xx、超时、TLS 错误、缺字段或错误版本。记录实际请求数、并发峰值及等待时间。文件替身能分别在读取、临时文件写入、最终替换和第 N 个提交时失败；进程替身记录 cwd、参数数组和退出码。
